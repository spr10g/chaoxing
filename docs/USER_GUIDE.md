# 学习通批量工作台 0.2.0

## 启动与升级

从 GitHub Releases 下载 Windows x64 程序 ZIP，解压完整目录，双击 `学习通工作台.exe`。不使用 CMD，也不依赖电脑控制或 Codex。

请保留 EXE 旁的 `_internal` 目录。设置与登录状态存储在 `%LOCALAPPDATA%\ChaoxingDesktop`，更新时只替换程序目录，不删除数据目录。

源码包是供开发使用的独立下载项，不需要将源码复制到程序目录。源码仓库不含任何真实账号、Cookie、API Key 或本机数据库。

## 多课程与两条队列

1. 在“连接与设置”登录。
2. 在“任务与进度”的课程列表点击第一列勾选多门课程。
3. 点击课程名称查看各自章节，选择部分章节；或点击“勾选课程的全部章节”，为所有勾选课程选择整门课程。
4. 选择视频、AI 答题或两者，点击“启动所选课程”。章节在后台加载，单门课程读取失败会列出原因，其他课程继续。
5. 视频和答题队列独立推进，默认并发 4 和 2。AI 仅参与答题。自动任务与手动 AI 重做共享 AI 并发上限。

可分别暂停和恢复两条队列。配置变更自动保存，并发在下一轮启动时应用。API 整体故障只暂停答题，视频继续。

## 跨课程、跨章节审核

“答案审核”上方汇总全部答题章节；可以按课程及“仅异常题章节／完整可交卷／已交卷／交卷待核验”等状态筛选。

章节表和题目表均支持 Ctrl / Shift 多选及一键全选。选择多个章节后，下方显示这些章节的题目；未选章节时显示当前筛选范围全部题目。题目可再筛选“需处理”或“校验通过”。

校验通过指题型、答案格式和选项映射等处理没有报错，不保证知识答案一定正确。

### 保存、交卷的区别

- **保存选中章节正常题**：将这些章节中已有的正常答案同步到平台草稿，即使同章有异常题也允许保存；不交卷。
- **保存选中题所在章节**：对选中题目涉及的章节执行上述保存，包含这些章节中其他已验证的正常答案。
- **提交选中章节**：逐份交整份章节测验。默认跳过有异常或未处理题目的章节，继续其他正常章节。
- **提交全部可交卷**：对当前课程和状态筛选范围中完整且校验通过的章节批量交卷，不用逐章点选。
- **本次允许含空题整章交卷**：默认关闭，仅影响本次“提交选中章节”；异常、未处理或答案不合法的题目留空。平台可能拒绝，或按未答处理；是否还能补交取决于课程规则。没有任何正常答案时不交空白卷。每次提交操作后此开关自动关闭，不影响自动队列的严格交卷检查。

批量操作结果逐章显示成功、失败、仍有异常、跳过或停止及原因。一章出错不会中断其他章节。正在运行的视频或其他章节不会阻止审核；仅同一个正在执行的任务可能被跳过，提示准确的原因。

### AI 重做与人工修正

- **AI 重做选中题**：勾选多道题后点击，真正重新请求 AI，跳过本地缓存，只更新选中题目。
- **AI 重做显示的异常题**：重做当前题目筛选及章节选择范围内的异常题，可跨课程、跨章节。
- AI 重做和人工修正均保留旧答案与错误历史；题目详情显示历史。
- 重做后的结果先本地保存并标为待审核，不自动保存到平台或交卷。随后可批量保存正常题、或在完整后批量交卷。
- 双击单道题人工修改选项。只锁定相关章节，无需停止所有任务。
- 当前 AI 支持范围仍为文字单选、多选、判断题。图片、未支持题型和无法可靠解码的题目会显示具体原因，重做不会绕过这些校验。

## 队列批量移除

在任务表中 Ctrl / Shift 多选，点击“移出选中任务”。等待任务不再执行；运行任务在检查点或当前请求返回后停止。其他课程、同章另一条队列的其他任务继续运行。

题目、答案、历史均保留。本轮重新扫描不会自动加回移出项；下一轮手动启动可再次加入。勾选“显示移出记录”可查看历史，审核页也能继续处理保留的题目。

已发出的保存或交卷请求无法撤回，程序会记录实际结果；请求结果不明确时必须先核验，避免自动重复交卷。

## 状态含义

执行状态与平台状态分别显示：

- **平台草稿已保存**：有成功同步草稿的记录，不代表交卷。
- **平台有草稿·本地有更新**：原草稿已保存，但 AI 重做或人工修改尚未重新同步。
- **平台草稿未核实**：没有足够的成功保存证据；不等于保存失败。
- **草稿同步失败·本地保留**：本次平台保存失败，答案仍在本地。
- **任务未完成**：平台任务列表仍显示未完成；核验本身不保存答案，也不覆盖此前的草稿保存证据。
- **未开始·已停止／处理中·已停止**：区分尚未执行和执行过程中取消。早期历史记录没有阶段信息时不会凭文案推断断点。
- **交卷结果待核验**：请求已发出但结果不明确，禁止盲目自动重交。选中该章节点击核验；核验不发交卷请求。

## 连接与数据

DeepSeek 默认 `https://api.deepseek.com`、`deepseek-flash`，使用 OpenAI 兼容协议，官方接口默认非思考模式。不要填写 `/anthropic` 或带 `/chat/completions` 的完整 URL。其他兼容服务可修改地址和模型。

账号、Key、Cookie 保存在本机数据及导入备份中，未加密。脱敏错误记录为 `last-error.json`；Cookie 过期后需要重新登录。

## 开发和验证

Python 3.12 x64；依赖为 `requirements.lock.txt`。运行 `desktop_main.py`；测试命令为 `python -m unittest discover -s tests -v`，布局检查为 `python tests/ui_layout.py`。安装 PyInstaller 后使用 `scripts/build.ps1` 构建。当前构建会携带所用 Python 必需的附加 TLS 资源，并在打包冒烟检查中创建 TLS 上下文。

版本更新保留同一数据目录；需要完整移动运行数据时先关闭程序，再备份整个数据目录。运行测试使用的诊断目录不会进入发行包。
